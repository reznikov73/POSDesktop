## 1. Что это

POS Desktop — оболочка рабочего стола Windows: панель приложений у левого края,
статус-бар сверху, панель сервисов снизу, прозрачная рабочая область с плитками
на обоях. Стек: **Rust + Slint**, без WebView.

## 3. Ключевые решения

1. **Rust + Slint 1.18**, только Windows. WebView/Tauri отвергнуты по памяти.
2. **Программный рендер по умолчанию** (`SLINT_BACKEND=winit-software`):
   18.8 МБ RSS против 63.5 МБ у GPU. Переопределяется переменной окружения.
3. **Четыре окна**: панель приложений (слева, выезжает), статус (сверху),
   сервисы (снизу), рабочая область (прозрачная, по габаритам плиток).
4. **Клик-сквозь** рабочей области — `SetWindowSubclass` + `WM_NCHITTEST`:
   внутри плитки `HTCLIENT`, вне — `HTTRANSPARENT`.
5. **Логи в корне проекта**, путь ищется по ближайшему `Cargo.toml` выше exe.
6. **Тема светлая** по умолчанию, палитра из макета: фон `#fbfcfc`,
   поверхности `#f1f4f5`, текст `#17181a`, акцент `#0c7f68`.

## 7. Грабли (проверено на практике)

1. **HWND появляется только после первого прохода цикла событий.** Стили
   применяются через `slint::Timer::single_shot(350 ms)`; сразу после `show()`
   `window_handle()` возвращает ошибку.
2. **`SetWindowPos(HWND_BOTTOM)` отправляет окно под обои** — плитки «мелькают
   и исчезают». Не использовать; рабочая область должна быть обычным окном.
3. **Slint `background: transparent` работает** — 97.4 % пикселей с alpha=0.
4. **`slint::Weak<T>` можно передавать в поток** — на этом построен триггер-воркер.
5. **WS_EX_APPWINDOW нужно снимать**, иначе кнопка на панели задач остаётся.
6. **`clippy -D warnings`** — сборка падает на любом предупреждении.
7. `window_handle()` в Slint — свой тип `slint::WindowHandle`, у него вызывается
   трейтовый `.window_handle()` из `raw-window-handle`.
8. **Хоткей `Ctrl+Alt+1` может быть занят** другой программой — код логирует
   `GetLastError` и автоматически пробует `Ctrl+Alt+Shift+1`.
9. **Несколько экземпляров приложения** держат горячие клавиши и мешают тестам:
   перед проверкой убивать старые процессы (`Get-Process posdesktop | Stop-Process -Force`).
10. **Окно рабочей области — `WS_EX_NOACTIVATE`**: перетаскивание не полагается
    на поток событий winit — нажатие сообщает Slint (`tile-pressed`), а движение
    и отпускание опрашиваются `GetCursorPos`/`GetAsyncKeyState`.
11. **Координаты раскладки — логические px**, а `WM_NCHITTEST` приходит в
    физических: зоны клик-сквозь умножаются на `scale_factor()` при установке и
    после каждого перетаскивания.
12. **Привязка — шаг 8 px** (ТЗ §6.1), размеры плиток кратны 88 px. Магнит к
    узлам 88 px проверялся и отклонён: штатные координаты (y=96 → 88) прыгали
    на 8 px при отпускании.
13. **Сквозной тест drag пишет в `%APPDATA%`** — запускать только с подменённым
    `APPDATA` (`scripts/drag-check.ps1`), иначе тест перезапишет раскладку
    пользователя.
14. **Кнопки на панели задач** убираются снятием `WS_EX_APPWINDOW` и установкой
    `WS_EX_TOOLWINDOW`; после смены стиля нужно `ShowWindow(SW_HIDE)` +
    `SW_SHOWNOACTIVATE`, иначе кнопка висит до следующего показа окна.
15. **Консоль скрывается только своя**: `GetConsoleProcessList` должен вернуть 1.
    При запуске из терминала (`cargo run`, VS Code) в консоли живут другие
    процессы — скрывать её нельзя, иначе исчезнет окно терминала.
16. **Трей живёт в своём потоке**: `TrackPopupMenu` блокирует поток до выбора
    пункта, поэтому команды возвращаются колбэком и попадают в UI через
    `slint::invoke_from_event_loop` (слабые ссылки на окна остаются на UI-потоке).
17. **Slint-окно не держит внешний `SetWindowPos`**: позицию задаёт само приложение,
    поэтому «поднять панель и сфотографировать» не выходит. Для вёрстки есть
    `--panel-snapshot` (пишет BMP своим кодом), а `PrintWindow` с программным
    рендером отдаёт чёрный кадр.
18. **Нижняя панель уезжала под панель задач Windows**: панели док-режима надо
    ставить в рабочую область (`SPI_GETWORKAREA`), а не в габариты экрана.
19. **`Window.background` в Slint не делает окно непрозрачным**: между элементами
    просвечивал рабочий стол (`alpha = 0`). Фон рисуется явным `Rectangle` на весь
    размер окна — тогда в буфере 0 прозрачных пикселей (проверяется
    `--panel-snapshot`: печатает статистику альфы).
20. **Хоткеи на этой машине частично заняты** (код 1409): `Ctrl+Alt+1` и `Ctrl+Alt+3`
    держит другая программа, оболочка уходит на Shift-вариант и пишет об этом в лог.
    Проверка `scripts/hotkeys-check.ps1` читает лог и жмёт именно зарегистрированную комбинацию.
21. **`SHGetFileInfo` на `.lnk` отдаёт значок ярлыка**, а не приложения: настоящую
    иконку возвращает `IShellItemImageFactory` (`shell_icon`), `SHGetFileInfo`
    остался запасным путём.
22. **Короткие названия не матчатся по префиксу** (меньше 4 символов): «1С»
    подходило к «1С-Коннект» и плитка получала чужую иконку. Теперь коротким
    именам нужно точное совпадение, иначе — монограмма.
23. **`log` без фичи `std`** не даёт `set_boxed_logger`: сборка отдельного крейта
    (`cargo test -p posdesktop-shell`) падала, хотя весь workspace собирался.
24. **`Ctrl+Z` без фокуса не работает**: окна оболочки не забирают фокус (ТЗ §11.3),
    поэтому откат висит на глобальных `Ctrl+Alt+Z` / `Ctrl+Alt+Y` и на пунктах меню
    трея. Когда появится клавиатурный фокус в панели, добавим и `Ctrl+Z`.
25. **SQLite читается через системную `winsqlite3.dll`** (`#[link(name = "winsqlite3")]`,
    импорт-библиотека есть в Windows SDK). Новых зависимостей не добавляли; база
    открывается только на чтение, иначе Soroka с WAL могла бы блокироваться.
26. **Новая иконка трея уходит в «скрытые значки»** Windows — это поведение ОС,
    пользователь закрепляет её в параметрах панели задач. Проверять наличие
    иконки через `Shell_NotifyIconGetRect` в этом состоянии нельзя (E_INVALIDARG):
    `scripts/tray-check.ps1` дергает окно трея теми же сообщениями, что и Проводник.

## 10. Правила работы

- Интерфейс, комментарии, коммиты и документация — **на русском**.
- После каждого изменения: `cargo fmt`, `clippy -D warnings`, `tests`,
  `build --release`, коммит, синхронизация в `E:`.
- Версия поднимается `scripts/version.ps1 -Bump patch`.
- Новые зависимости — только при явной необходимости; целевой бюджет
  памяти ≤60 МБ, CPU в покое ≤0.2 %.
- Перед изменением поведения окон — сверяться с `docs/D0-measurements.md`.
