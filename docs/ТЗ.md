**Версия:** 1.0
**Статус:** основание для разработки. Кодирование начинается только по явной команде владельца.

## 1. Общее

### 1.1. Назначение

POS Desktop — персональная оболочка рабочего стола Windows. Собирает в одном месте то, что обычно разнесено по «Пуску», трею, рабочему столу и браузеру: запуск приложений, избранные ссылки, состояние инфраструктурных сервисов, почту и ИИ-помощника.

Оболочка работает поверх системы: не заменяет Проводник и панель задач, не требует повышения прав.

### 1.2. Принципы

1. **Ресурсы — приоритет №1.** Низкое потребление RAM и CPU важнее визуальных эффектов. Всё, что не проходит по бюджету, вырезается.
2. **Предсказуемость.** Ни одно действие не выполняется без явного подтверждения, если оно необратимо.
3. **Локальность.** Данные пользователя остаются на диске; наружу уходит только запрос к GigaChat.
4. **Честность измерений.** Любая цифра в требованиях имеет методику проверки; неподтверждённые числа помечены как цели.

### 1.3. Границы

**Входит:**

- четыре типизированные панели у краёв экрана;
- рабочая область с плитками, группами и виджетами;
- виджет почты с интеграцией Soroka;
- ИИ-ассистент с реестром инструментов и подтверждениями;
- кастомизация панелей и раскладок;
- установка, обновление, автозапуск, трей.

**Не входит:**

- замена Проводника, панели задач и системной оболочки;
- многопользовательский режим и синхронизация между устройствами;
- мобильные и веб-версии;
- повышение прав (UAC) и управление системными службами `services.msc`;
- магазин расширений.

### 1.4. Термины

| Термин | Значение |
|---|---|
| Панель | Типизированный регион у края экрана: `apps`, `ai`, `status`, `services` |
| Триггер | Зона 6 px у края; определяется опросом курсора, без отдельного окна |
| Док-режим | Панель постоянно видна полосой фиксированной толщины |
| Hover-режим | Панель раскрывается при наведении и сворачивается при уходе курсора |
| Рабочая область | Центральная зона с плитками и группами (desktop-слой) |
| Плитка | Объект запуска или виджета, кратный 88 px |
| Сервис | Дочерний процесс оболочки либо процесс, опознанный по PID-файлу |
| Tool-call | Вызов инструмента ИИ со структурированными аргументами — единственный канал передачи внешнего контента модели |

### 1.5. Гейт старта

Документ фиксирует, **что** и **как** делать. Разрешение на код даёт владелец отдельной командой. До неё допускается только чтение материалов и планирование.

## 2. Целевой сценарий

1. Утро: пользователь видит верхнюю панель с почтой, VPN и бэкапом, нижнюю — с сервисами проекта.
2. Наводит курсор на левый край — выезжает каталог приложений, находит 1С, запускает.
3. Перетаскивает часто используемое приложение на рабочую область — появляется плитка.
4. Справа вызывается ИИ: «сколько непрочитанных в рабочем ящике» — ответ без открытия почты.
5. ИИ просит удалить файл — получает карточку подтверждения; после удаления 10 секунд работает отмена.
6. Вечером сервис падает — нижняя панель краснеет, приходит уведомление, ИИ предлагает посмотреть логи.

## 3. Ключевые архитектурные решения

### 3.1. Слой UI

Требование владельца — минимальные RAM и CPU — определяет выбор UI.

| Вариант | RAM (цель) | CPU в покое | Диск | Статус |
|---|---|---|---|---|
| **Rust + Slint** | ≤60 МБ | ≤0.2 % | 8–15 МБ | основной |
| Rust + egui | ≤60 МБ | ≤0.2 % | 8–15 МБ | резерв |
| Tauri 2 + WebView2, одно окно | ≤180 МБ | ≤0.6 % | 10 МБ + рантайм | альтернатива |

Числа для нативных вариантов — целевые ориентиры: порог приёмки фиксируется замером D0. Для Tauri оценка основана на публичных замерах и расчёте по процессам.

Финальный выбор фиксируется после D0 и не пересматривается в ходе разработки.

### 3.2. Z-слои

| Слой | Что | Z-порядок |
|---|---|---|
| Desktop-слой | Рабочая область: плитки, группы, виджеты | Ниже обычных окон, выше обоев |
| Overlay-слой | Панели | Всегда поверх, скрываются в fullscreen |
| Системный | Трей, уведомления | Штатные механизмы Windows |

Рабочая область не должна висеть над приложениями — иначе плитки закрывают работу. Опция «рабочая область поверх всего» выключена по умолчанию.

**Встраивание в рабочий стол.** Desktop-слой размещается через окно `WorkerW` (как Rainmeter). `WorkerW` пересоздаётся при смене темы, обоев, `F5` на рабочем столе, выходе из fullscreen и обновлениях Explorer, поэтому:

- подписка на `WM_THEMECHANGED`, `WM_DWMCOMPOSITIONCHANGED`, `WM_DISPLAYCHANGE`;
- проверка существования родителя раз в 5 секунд и перепривязка;
- после двух неудачных перепривязок — автоматический переход в режим «Окно-дашборд» (обычное окно по хоткею) с уведомлением;
- режим «Окно-дашборд» доступен вручную.

### 3.3. Оконная модель

| Стек | Окна | Обоснование |
|---|---|---|
| Slint | 4 окна панелей + 1 окно рабочей области на монитор | Нативные окна дешёвы, изоляция сбоев |
| Tauri | одно окно-контейнер, панели и область — DOM-регионы | 5 webview-окон дают 250–400 МБ |

Общее: триггеры — **без окон**, опрос `GetCursorPos` 30 Гц (≈0.05 % CPU) со сверкой с краями мониторов. Такой подход не ломает ресайз окон у краёв и не перехватывает клики.

### 3.4. Клик-сквозь

Прозрачная рабочая область обязана пропускать клики вне плиток. Два допустимых механизма:

| Вариант | Суть | Плюсы | Минусы |
|---|---|---|---|
| **А. Одно окно + `WM_NCHITTEST`** | Для пустых зон возвращается `HTTRANSPARENT` | Один объект; точность до пикселя | Сабклассинг WndProc: `SetWindowSubclass` поверх winit или собственный windowing через Slint platform API |
| **Б. Окно на плитку/группу** | Каждый объект — маленькое окно по своим размерам | Клик-сквозь не нужен; изоляция сбоев | 20–40 окон, сложнее drag и группировка |

Дёргать `WS_EX_TRANSPARENT` глобально по позиции курсора запрещено: гонки и «залипание» оболочки.

Выбор — по результатам D0. Вариант Б увеличивает M2 на 1–2 недели.

### 3.5. Полноэкранный режим

- Детект: `GetForegroundWindow` + `GetWindowRect` каждые 500 мс; различаются exclusive fullscreen, borderless fullscreen и maximized (последнее — не fullscreen).
- В fullscreen скрываются **все** панели; опция «оставлять dock» выключена по умолчанию.
- Рабочая область в fullscreen не видна (desktop-слой).

### 3.6. Ресурсные бюджеты

| Метрика | Slint | Tauri |
|---|---|---|
| RSS в покое (дерево процессов) | ≤60 МБ | ≤180 МБ |
| RSS при активной работе | ≤120 МБ | ≤300 МБ |
| Рост RSS за 24 ч | ≤10 МБ | ≤10 МБ |
| CPU в покое | ≤0.2 % | ≤0.6 % |
| Холодный старт | ≤0.8 с | ≤1.5 с |
| Открытие панели | ≤200 мс | ≤200 мс |
| Диск (установщик) | ≤25 МБ | ≤25 МБ |

### 3.7. Ориентиры

| Источник | Что берём |
|---|---|
| Raycast | декларативные инструменты, песочница, журнал действий |
| Seelen-UI | опыт Tauri-оболочки, `WS_EX_TOOLWINDOW`, распространение |
| Rainmeter | декларативные виджеты, desktop-слой, минимализм ресурсов |
| PowerToys | индексация Start Menu через IShellLink, кэш иконок |
| Cairo Shell | tray-UX (замену shell не делаем) |

## 4. Архитектура приложения

### 4.1. Модули

| Модуль | Технология | Ответственность |
|---|---|---|
| `shell/` | Rust + windows-rs | окна, z-порядок, триггеры, fullscreen, DPI, трей, автозапуск |
| `ui/` | Slint (или TS + WebView2) | панели, рабочая область, виджеты, анимации |
| `core/` | Rust | раскладка (единственный владелец), настройки, миграции, undo |
| `integrations/` | Rust | Soroka (IPC/SQLite), IMAP, процессы сервисов, GitHub API |
| `ai/` | Rust | GigaChat, реестр инструментов, подтверждения, журнал, корзина |
| `platform/` | Rust + windows-rs | иконки `.exe`/`.lnk`, IShellLink, хоткеи, уведомления |

### 4.2. Владение состоянием

- `layout.json` и `settings.json` пишет только Rust.
- UI присылает команды (`move_tile`, `resize_tile`, `reorder_panel`) и получает новое состояние.
- При расхождении побеждает состояние ядра; UI откатывается.

### 4.3. Мультимониторность и DPI

- Раскладка хранится на каждый монитор, ключ — идентификатор дисплея.
- По умолчанию панели на основном мониторе; настраивается.
- При отключении монитора раскладка уходит в архив; при подключении — диалог «применить из архива / создать новую».
- Координаты в логических пикселях; при смене DPI окна пересоздаются, раскладка пересчитывается.

### 4.4. Системные события

| Событие | Реакция |
|---|---|
| Блокировка сессии (`WM_WTSSESSION_CHANGE`) | панели скрываются, анимации останавливаются; после разблокировки — восстановление |
| RDP-реконнект или смена разрешения (`WM_DISPLAYCHANGE`) | перечисление мониторов, перезагрузка раскладки, пересоздание окон |
| Подключение/отключение монитора | архив раскладки / предложение применить из архива |
| Hot-plug во время drag | перетаскивание отменяется, плитка остаётся на последней валидной позиции, одно уведомление |
| Смена темы Windows | перепривязка desktop-слоя, перерисовка рамок |
| Завершение сеанса | сохранение раскладки и чата, остановка сервисов по политике |

## 5. Панели

### 5.1. Модель

| Параметр | Значения | По умолчанию |
|---|---|---|
| Тип | apps / ai / status / services | фиксирован по назначению |
| Край | left / right / top / bottom | apps-left, ai-right, status-top, services-bottom |
| Режим | hover / dock / hidden | apps, ai — hover; status, services — dock |
| Размер | толщина 44–64 px; длина 320–480 px | 360 (apps), 420 (ai) |
| Плотность | compact / comfortable | compact |

### 5.2. Левая — приложения

- Источники: Start Menu (`%APPDATA%` и `%ProgramData%`) через IShellLink; ручные записи (`.exe`, `.lnk`, `.url`, скрипт).
- Иконки: `SHGetFileInfo` → HICON → PNG в `%APPDATA%\POSDesktop\icons\<sha256>.png`; при ошибке — моноиконка. Кэш обновляется при старте и по кнопке.
- Категории: автоопределение по пути + ручное переопределение; «Мои программы» для ручных записей.
- Действия: запуск, закрепить в избранном, открыть расположение, свойства, скрыть из каталога.

### 5.3. Правая — ИИ

История диалога, многострочный ввод, быстрые действия, индикация вызова инструментов («Читаю почту…») с возможностью отмены. Полное описание — §8.

### 5.4. Верхняя — избранное и статус

- Слева: плитки 32×32 (программы, папки, URL), перетаскивание для порядка.
- Справа: почта (бейдж + разбивка), POSvpn, бэкап, CI, часы. Hover — детализация, клик — действие.

### 5.5. Нижняя — сервисы

Список: иконка, имя, статус, uptime, кнопки «Запустить», «Остановить», «Логи». Ошибка — красная точка и уведомление.

### 5.6. Активация и горячие клавиши

| Правило | Значение |
|---|---|
| Задержка открытия | 250 мс |
| Задержка закрытия | 350 мс |
| Зона триггера | 6 px у края, исключая 32 px от углов |
| Закрытие | Esc, клик вне, повторный хоткей |
| Закрепление | булавка в заголовке; в dock неактивна |

| Действие | Комбинация |
|---|---|
| apps | `Ctrl+Alt+1` |
| ai | `Ctrl+Alt+2` |
| status | `Ctrl+Alt+3` |
| services | `Ctrl+Alt+4` |
| Поиск | `Ctrl+Alt+Space` |
| Свернуть все панели | `Ctrl+Alt+Esc` |

Глобальные хоткеи регистрируются через `RegisterHotKey`; при занятой комбинации — понятное сообщение и предложение изменить. Молчаливый отказ запрещён. `Alt+Space`, `Win+Esc`, `Alt+1…4` не используются: заняты системой и приложениями.

### 5.7. Перенос панелей

Панель — типизированная сущность: перенос меняет край, но не тип. На одном краю — одна панель. При конфликте — диалог «Поменять местами?» с превью. Минимальная толщина 44 px. Край с системной панелью задач — предупреждение.

## 6. Рабочая область

### 6.1. Сетка

Шаг 8 px; плитки кратны 88 px (88/176/264/352); отступ 8 px; пересечения не допускаются (автосдвиг). Сетка применяется только к рабочей области — панели живут по density-layout.

### 6.2. Объекты

| Тип | Мин. размер | Примечание |
|---|---|---|
| Плитка-запуск | 88×88 | приложение, папка, URL, скрипт |
| Плитка-виджет | 176×88 | почта, погода, календарь, заметки, диски, система, ИИ-промпт |
| Группа | 264×176 | контейнер с заголовком |
| Разделитель | 8×8 | опционально |

### 6.3. Действия

Создать / переместить / изменить размер / сгруппировать / удалить / отменить. Undo — 20 действий, `Ctrl+Z` и `Ctrl+Shift+Z`.

### 6.4. Раскладки

Автосохранение; именованные пресеты (`Ctrl+Alt+Shift+1…9`); заводские «Работа», «Минимум», «Отладка» (копируемые); сброс с бэкапом; экспорт и импорт JSON.

### 6.5. Синхронизация

Drag-and-drop обрабатывает UI, но фиксирует Rust командой. Таймаут подтверждения — 500 мс (adaptive 300–800 мс). Во время активного перетаскивания откат не выполняется: UI держит локальный предпросмотр до подтверждения.

## 7. Интеграции

Профиль: https://github.com/reznikov73.

### 7.1. Карта

| Репозиторий | Язык | Интеграция |
|---|---|---|
| Soroka | Rust | глубокая: почта и ключ GigaChat |
| Klavium | Rust | опционально: индикатор запуска и вызов хоткея |
| POSCloud | Go | сервис: старт/стоп, healthcheck HTTP |
| POSvpn | Go | сервис: старт/стоп, healthcheck через IP Helper |
| grm-autobackup | Go | сервис: старт/стоп, healthcheck по mtime |

### 7.2. Soroka: каналы

| Канал | Когда | Что даёт |
|---|---|---|
| IPC (named pipe) | Soroka запущена | **основной**: события нового письма, счётчики, тела по запросу |
| SQLite read-only | Soroka закрыта | резерв: счётчики и заголовки |
| IMAP напрямую | Soroka не установлена/не запущена | только счётчики |
| Офлайн | ничего недоступно | кэш последней синхронизации, серый бейдж |

**WAL.** База Soroka работает в режиме WAL: чтение `read-only` требует доступа к `-shm`, иначе возможен `immutable=1` со stale-чтением. Поэтому свежесть обеспечивает IPC, а БД — резервный канал.

### 7.3. Ключ GigaChat

Сейчас Soroka хранит ключ в `%APPDATA%\Soroka\gigachat.json` (открытый JSON); пароли ящиков — в `accounts.json`. DPAPI-хранилища пока нет.

План M0: добавить DPAPI-хранилище `secrets.bin`, миграцию из JSON; после этого оболочка читает ключ только оттуда. До M0 используется переменная `SOROKA_GIGACHAT_KEY` — временно, не дольше 4 недель, с пометкой в интерфейсе.

### 7.4. Klavium

- Определяется по именованному мьютексу `Global\KlaviumRunning`; при запуске в верхней панели появляется иконка голосового ввода.
- Клик вызывает хоткей Klavium через `SendInput`.
- Оболочка не запускает Klavium автоматически и не редактирует его настройки.

### 7.5. Сервисы

| Сервис | Запуск | Healthcheck |
|---|---|---|
| POSCloud | `poscloud.exe serve --config <cfg>` | `GET http://127.0.0.1:8080/health` каждые 15 с |
| POSvpn | `posvpn.exe up --config <profile>` | `GetAdaptersAddresses`: TUN-адаптер существует |
| grm-autobackup | `grm-autobackup.exe run --daemon` | mtime `last_backup.txt` за последние N часов |

Состояния: `stopped → starting → running → stopping → stopped`, плюс `error` и `unknown` (PID есть, процесса нет). Логи: `%APPDATA%\POSDesktop\logs\services\<name>.log`, ротация 5 МБ × 5.

## 8. ИИ-ассистент

### 8.1. Роль и стиль

Кратко, технически, без вежливости. Списки и команды. Ошибка — причина и действие. Ответ ≤200 слов, длинное — под раскрытие.

### 8.2. Инструменты

| Инструмент | Класс | Подтверждение |
|---|---|---|
| `mail.count`, `mail.list`, `mail.summary` | read | нет |
| `services.status`, `apps.list`, `files.search` (в рабочих папках) | read | нет |
| `apps.launch` (из каталога) | action | нет |
| `apps.launch` (произвольный путь) | action | да |
| `files.open`, `files.move`, `files.rename` | write | да |
| `services.start`, `services.stop` | write | да |
| `files.delete`, `mail.delete` | destructive | двойное + undo 10 с |
| `script.run` | destructive | двойное, только из whitelist |
| `panels.*`, `desktop.move_tile` | ui | нет |

### 8.3. Безопасность

1. **Внешний контент — только через tool-call.** Тело письма, имя файла, содержимое страницы не попадают в prompt свободным текстом: модель получает структурированные поля.
2. **Остаточный риск принимается осознанно.** Суммаризация письма выполняется отдельным вызовом LLM, и этот вызов читает недоверенный текст. Выход суммаризатора — тоже недоверенные данные: он передаётся основной модели как поле данных, ограничивается по длине и очищается от управляющих символов. Аргументы инструментов валидируются по схеме и белым спискам (пути, id, имена приложений).
3. **Подтверждения.** write — карточка с превью; destructive — двойное подтверждение, чекбокс «понимаю, что безвозвратно», корзина `%APPDATA%\POSDesktop\trash\` и окно отмены 10 с.
4. **Журнал.** `ai-journal.log`: время, инструмент, аргументы (пути вне рабочих папок — SHA-256), результат, длительность. Ротация 5 МБ × 5, хранение 30 дней.
5. **Whitelist скриптов** — путь и SHA-256; изменение файла блокирует запуск. Редактируется без повышения прав.
6. **Рабочие папки** — единственная зона изменений; вне их `files.delete` запрещён полностью.

### 8.4. Контекст

Структурированный JSON: раскладка панелей, статусы сервисов, счётчики почты, активные приложения. История — 20 сообщений, дальше архив.

### 8.5. Ошибки

| Случай | Поведение |
|---|---|
| Нет ключа | «GigaChat не настроен» + инструкция |
| Нет сети | «Нет соединения» + «Повторить» |
| 429 | backoff 2/4/8 с, затем graceful-сообщение |
| Отказ инструмента | причина + альтернатива |

### 11.2. Уведомления

Windows Toast через WinRT требует AppUserModelID: для unpackaged-сборки создаётся ярлык с AUMID в меню «Пуск». Альтернатива — in-app тост 4 с с паузой при наведении. Не более 3 одновременно.

### 11.3. Доступность

- Tab внутри панели, фокус-ловушка, Esc, видимый фокус 2 px.
- Клавиатурный доступ обязателен (`Ctrl+Alt+1…4`).
- **Фокус в no-activate окне.** Панели создаются с `WS_EX_NOACTIVATE`, чтобы наведение не отбирало фокус. При открытии с клавиатуры или клике в поле ввода: временно снимается `WS_EX_NOACTIVATE`, вызывается `SetForegroundWindow`, после потери фокуса флаг возвращается. Если ОС не отдаёт фокус — fallback `AttachThreadInput` и подсказка «нажмите Tab». Проверяется в D0.
- Контраст текста ≥4.5:1; `prefers-reduced-motion` → без движения, только прозрачность.
- Тест с NVDA: озвучивание панелей и плиток.

### 11.4. Анимации

Выезд 180–220 мс, `cubic-bezier(0.2, 0, 0, 1)`; появление плитки 120 мс; пульсация бейджа 600 мс однократно; всё отключается настройкой и системным флагом.

### 17.6. Скрипты

| Скрипт | Назначение |
|---|---|
| `setup.ps1` | проверка rustc/cargo/link.exe/git/gh, `gh auth status`, создание приватного репозитория при отсутствии |
| `version.ps1` | patch-инкремент версии в `Cargo.toml` и WiX-шаблоне; `-Set 1.2.3` для ручного |
| `build.ps1` | release-сборка, копирование exe в `dist/POSDesktop-<ver>.exe`, вывод размера |
| `installer.ps1` | сборка MSI через WiX (`cargo wix`), копирование в `dist/`, подпись при наличии сертификата |
| `release.ps1` | оркестратор: fmt → clippy → test → build → installer → version → commit → push → `gh release create` по флагу |

Общие требования: флаги `-NoPush`, `-NoTests`, `-Release`, `-Bump minor|patch`; ненулевой код возврата при ошибке; вывод шагов с таймингами.

### 17.7. Пайплайн «изменение → релиз»

1. Правка кода, сохранение (format on save).
2. `Ctrl+Shift+B` → `publish`.
3. `cargo fmt --check`, `cargo clippy -- -D warnings`, `cargo test`.
4. `cargo build --release` → `target/release/posdesktop.exe`.
5. `installer.ps1` → `dist/POSDesktop-<ver>-x64.msi` (WiX).
6. `version.ps1` → patch-инкремент (только в `publish`).
7. `git add -A`, коммит по шаблону `<type>(<scope>): <кратко> [v<ver>]`; типы: `feat`, `fix`, `refactor`, `docs`, `chore`, `test`.
8. `git push origin main`.
9. По флагу `-Release`: `gh release create v<ver> dist/*`.

Гарантии: при сбое любого шага цепочка останавливается; коммит и push не выполняются, если упали сборка, clippy или тесты; артефакты прошлой успешной сборки не перезаписываются.

| Удаление | штатный MSI-uninstall; данные в `%APPDATA%` сохраняются, удаляются отдельным пунктом |
| Подпись | OV-сертификат или self-signed с инструкцией; EV не требуется |
| Portable | ZIP рядом с MSI, без регистрации, настройки рядом с exe по флагу `--portable` |

## Приложение Б. Принятые решения

| № | Решение | Почему |
|---|---|---|
| 1 | Rust-ядро, Slint как основной UI | минимальные RAM/CPU при жёстком требовании владельца |
| 2 | Панели и рабочая область в разных Z-слоях | иначе плитки висят над приложениями |
| 3 | Триггеры опросом курсора, без окон | не ломает ресайз у краёв и не перехватывает клики |
| 4 | Клик-сквозь только через проверенный механизм (А/Б) | глобальное переключение флага даёт гонки и залипание |
| 5 | Панели типизированы, Alt-привязка к типу | перенос панели не меняет её смысл |
| 6 | Сетка 88 px только в рабочей области | панели не кратны 88 |
| 7 | Замер ресурсов по дереву процессов | иначе WebView2-процессы не учитываются |
| 8 | IPC основной канал почты, SQLite — резерв | WAL и read-only дают stale-чтение |
| 9 | Ключ GigaChat — один владелец (Soroka) | не дублировать секреты |
| 10 | ИИ: классы действий и подтверждения | необратимое — только с человека |
| 11 | Внешний контент только через tool-call | снижение риска инъекций |
| 12 | WiX MSI, per-user | без UAC, штатное обновление и удаление |
| 13 | Репозиторий приватный на старте | публикация — отдельное решение |
| 14 | Автосборка и автокоммит после изменений | владелец хочет постоянный рабочий артефакт |
